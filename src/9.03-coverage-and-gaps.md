## What the coverage figure means

The book measures itself against the game's own Python. Every module of the decompiled source is assigned by a rule in the coverage tool's rule file (the longest matching path prefix wins) to one chapter, or to the skip list of libraries described below. The coverage tool counts a module as cited when some system chapter names it: by its path in the decompiled source, by its path under its package root, or by its bare file name when no other module has that name. Each chapter's File index then says how far it read each module: `deep` (read and explained), `skim` (read for the table) or `listed` (only its names read). The table "Coverage per chapter" below repeats the cited counts and adds those depths; its **Other** column counts modules a File index names without one of these three words, and its **Empty** column counts the modules whose only statements are imports, `pass` or a docstring (package markers and re-export files), whatever word their File index gives them.

A full figure therefore says that no assigned module was forgotten. It does not say that every module is explained: a `listed` module may be named in its File index and nowhere else. After the second pass's deepening (2026-10-13), almost every module still listed is an empty one; the figures below give the counts. The reading guide and these appendices are left out of the count by design, since the module index names every module.

## What it does not measure

- **Modules that did not decompile.** The coverage tool's module manifest is built from the `.py` files the decompiler produced. A module whose bytecode it could not turn back into source is not in the manifest, so it cannot lower the figure. The table "Failed decompiles" below lists every `.pyc` under `core/` and `simulation/` with no `.py` (the 37 standard-library failures are left out), the chapter the rule file would give it (or its skip rule, or UNMAPPED where no rule matches) and the chapters that name it. The decompiler's own failure list is incomplete, so the table is built from the files themselves.
- **Native code.** Logic inside the executable or the engine library is outside the manifest. Chapters describe it from strings (for the engine library also its C++ class names and the protobuf descriptors it embeds) and from what the Python sends to it, and label it Inferred where they could not read it. The client's code is encrypted ([0.02](0.02-architecture.md)) and is never decrypted for this book.
- **Tuning.** The figure counts code, not tuning records. How tuning is built and merged is in [0.03 The tuning system](0.03-tuning-system.md), and every value in [9.01 Every number, in one table](9.01-numbers-index.md) says where it came from: a tuning build, the live merge, a code default, patch data or a count over code or files.
- **Packs that are not installed.** The base game code ships every pack's scripts, so pack modules are in the manifest and counted, but only installed packs run. The other packs' tuning and files exist here only as patch data; the table "Packs that exist here only as patch data" below lists them, and [9.04 Pack index](9.04-pack-index.md) shows where each is described.
- **Libraries.** The coverage tool's rule file skips `base/` (the Python standard library EA ships), `core/google/` (the protobuf runtime) and the Cython build shim.

## How chapters worked around failed decompiles

- **Rescue one function at a time.** The per-function decompiler decompiles single functions out of a `.pyc` whose module as a whole fails. [6.01](6.01-crafting-cooking.md) read `crafting_interactions` this way (`StartCraftingMixin`, `CraftingPhaseSuperInteractionMixin`), and [0.02](0.02-architecture.md) read `distributor/ops.py` this way, where 266 of its 269 class bodies (`Op`, its 267 subclasses and `DistributionSet`) decompiled.
- **Read the bytecode.** Where a function will not decompile either, chapters read the bytecode itself: [0.02](0.02-architecture.md) counted the `Field` declarations of `sims/sim.py` and found the one `c_api` entry point of `core/macros.py` there, and [1.04](1.04-debug-cheats-telemetry.md) read the console command modules (`sim_commands`, `statistic_commands`, `memory_commands` and others) from bytecode.
- **Strings and tuning.** A module's string constants and the tunables it exposes in tuning often say enough: [7.03](7.03-thumbnails-gallery.md) read the gallery upload field of `venues/venue_tuning.py` from its strings and the live tuning.

Each chapter labels the claims it made this way. In the "Failed decompiles" table, the **Named in** column shows which of these methods the chapter's own sentence names next to the module. The last generated section, "What each chapter could not read", is the first sentence (two when the first is a short label) of every item in each system chapter's Limits section.

**[0.02 Architecture: the executable, the engine library and the Python](0.02-architecture.md#limits)**

- **Missing packs.** Services gated to packs not installed here (EP02, EP03, EP05, EP08, EP10, EP11, EP14 to EP17, EP19 to EP21, SP13, SP22) are constructed and dropped at registration on this install, so they never run; what they do is known only from their code.
- **Delta tuning lists only overrides**, so "code default" values above are what the game uses unless a pack's own tuning sets them.
- The file and directory watcher, reload and GSI HTTP services exist in the code but are switched off in retail, so their behaviour was not observed.
